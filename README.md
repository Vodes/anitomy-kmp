# anitomy-kmp

Kotlin Multiplatform bindings for the C++23 rewrite of
[Anitomy](https://github.com/erengy/anitomy). The library preserves Anitomy v2's
ordered output, duplicate element kinds, and UTF-8 byte positions.

The upstream parser is pinned as a Git submodule at
`8498b538f5ddeedaef1b3fa5ad4bf6d67dd67d35`.

## Use

Add the Styx repository and the multiplatform dependency:

```kotlin
repositories {
    maven("https://repo.styx.moe/releases")
}

kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("pw.vodes:anitomy-kmp:<version>")
        }
    }
}
```

Parse a release name from common code:

```kotlin
import pw.vodes.anitomy.ElementKind
import pw.vodes.anitomy.parse

val elements = parse("[Group] Show - S02E03v2 [1080p].mkv")
val episode = elements.first { it.kind == ElementKind.EPISODE }

println(episode.value)    // 03
println(episode.position) // byte offset in the UTF-8 input
```

`parse` returns elements in upstream order. A kind can occur more than once, so
the result is deliberately a `List<Element>` rather than a map. `Options` exposes
all ten switches supported by Anitomy v2.

## Targets

| Kotlin target | Runtime platform | Native implementation |
| --- | --- | --- |
| `jvm` | Linux x64/ARM64, Windows x64, macOS ARM64 | Packaged JNI library |
| `linuxX64` | Linux x64 | Static C ABI bridge |
| `linuxArm64` | Linux ARM64 | Static C ABI bridge |
| `mingwX64` | Windows x64 | Static C ABI bridge |
| `macosArm64` | Apple Silicon macOS | Static C ABI bridge |

The JVM and JVM bytecode target Java 17. On the JVM, the platform library is
extracted to a SHA-256-addressed directory below `java.io.tmpdir` and loaded once.

## Build

Clone submodules and use JDK 17:

```shell
git submodule update --init --recursive
./gradlew jvmTest
```

CMake 3.21 or newer and Ninja are required for native builds. The helper script
builds the C ABI archive and, when applicable, its JNI library:

```shell
CXX=g++ scripts/build-native.sh linuxX64
./gradlew linuxX64Test \
  -Panitomy.nativeLibraryDir.linuxX64=build/native/linuxX64
```

For GNU targets, `libanitomy-bridge.a` is self-contained: the build folds in only
the C++ runtime objects required by the bridge. Do not package separate
`libstdc++` or `libgcc` archives with the Kotlin/Native publication.

Linux Kotlin/Native artifacts must be built with GCC 15.2 and an explicit glibc
2.17 sysroot. This keeps the bundled C++ runtime compatible with
Kotlin/Native's Linux linker baseline. The CI environment uses these pinned
conda-forge packages:

```text
gxx_linux-64=15.2.0
sysroot_linux-64=2.17
cmake=4.3.4
ninja=1.13.2
```

For `linuxArm64`, use the corresponding `gxx_linux-aarch64` and
`sysroot_linux-aarch64` cross packages and set CMake's system processor to
`aarch64`. Windows builds use MinGW GCC; macOS ARM64 builds use Apple Clang and
the system libc++.

To assemble a JVM artifact with all four JNI variants, point
`anitomy.jvmNativesDir` at a directory with this layout:

```text
linux-x64/libanitomy-kmp.so
linux-arm64/libanitomy-kmp.so
windows-x64/anitomy-kmp.dll
macos-arm64/libanitomy-kmp.dylib
```

## Tests

The shared suite runs through both JNI and Kotlin/Native. It covers all public
element kinds and options, upstream examples, Unicode byte positions, ownership,
and the Styx downloader regression corpus. The raw Anitomy v2 result is the
golden behavior; downloader-specific title repair is intentionally not part of
this binding.

## Releases

Remote publishing is allowed only when `HEAD` has exactly one semantic version
tag such as `v1.2.3`, and `releaseVersion` matches that tag:

```shell
./gradlew publishAllPublicationsToStyxRepository -PreleaseVersion=1.2.3
```

The release workflow publishes the root artifact as `pw.vodes:anitomy-kmp` and
the target variants generated by Kotlin Multiplatform. It reads repository
credentials from `STYX_REPO_TOKEN` and `STYX_REPO_SECRET`.
